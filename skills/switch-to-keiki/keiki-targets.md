# Choosing the Keiki target

Identify the source integration, its exact API generation, and the active behavior before choosing a Keiki surface. Keiki runs messaging channels for agents. A provider integration that sends to arbitrary recipients, manages Apple identities, or processes raw message events may need capabilities beyond Keiki's public agent interfaces.

Use the [iMessage capability reference](./imessage-capabilities.md) to check feature-level mappings and the [external harness example](./examples/external-harness.md) to compare the raw HTTP boundary.

## Choose the turn runtime

| Current boundary | Keiki surface to evaluate | Migration implications |
| --- | --- | --- |
| The application owns a model loop or deterministic reply handler behind an HTTPS receiver | [External harness in push mode](https://onkeiki.com/docs/external-harness#configure-an-agent) | Keep the handler and hosting model where possible. Adapt the receiver to signed, asynchronous turns and use scoped delivery and completion calls. Prove that source behavior still holds when Keiki batches, steers, or suppresses inbound messages. |
| The application runs locally, behind a firewall, or intermittently | [External harness in relay or inbox mode](https://onkeiki.com/docs/external-harness#relay-mode) | Relay forwards signed turns from a queue to the application. Inbox long-polls and uses leased claims. Compare queue, cancellation, arrival, and reaction semantics against the current lifecycle. |
| The migration is to a Keiki-managed agent with prompts and tools | [Cloud-served agents](https://onkeiki.com/docs/cloud-agents) and [AgentKit](https://onkeiki.com/docs/sdk#agent-lifecycle) | The dashboard or `kit.sync()` configures the agent. Keiki runs the turn loop, channel routing, and delivery. Map existing prompts, tools, state, and response behavior before moving the loop. |
| The application will run a Keiki SDK-defined agent on its own host | [AgentKit `kit.serve()`](https://onkeiki.com/docs/sdk#self-hosting-server) | The SDK syncs the configuration and serves its own Keiki-authenticated routes. Check runtime and hosting requirements. The server answers its turn request synchronously, while the external harness delivers and settles turns asynchronously. |
| Your backend provisions one agent per user or organization | [Partner deployments](https://onkeiki.com/docs/partner-deployments) | Keep the application tenant key in `external_ref`. Provisioning and channel connection have their own result statuses and billing effects. Choose the turn runtime separately. |
| A caller wants to invoke an agent through a model API | [Agents as models](https://onkeiki.com/docs/agent-api) | The OpenAI- or Anthropic-compatible gateway returns an API-channel completion. Use it for API callers. Channel delivery and inbound iMessage still require their own route. |

Preserve the existing application language, hosting and transport where they fit the target contract. Use a framework adapter when it fits the existing application and its runtime and the installed version smoke test passes. An existing HTTP application can call the raw turn endpoints. Keiki MCP can configure and inspect the platform, and turn-scoped MCP lets a harness call the tools available to its active turn. [AI SDK](https://onkeiki.com/docs/ai-sdk), [Flue](https://onkeiki.com/docs/flue), [Eve](https://onkeiki.com/docs/eve), [Keiki MCP](https://onkeiki.com/docs/mcp)

## Choose channel and delivery separately

- **Line and identity.** Choose between a dedicated purchased line, an eligible imported line, and a shared number. Confirm the actual line type, underlying provider, account eligibility, sender addresses and routing. A shared number needs first contact by join code. Keiki documents Linq line import and Photon account connection. Confirm the exact line and credential eligibility before planning to retain a number. Group support on a dedicated `blooio` line does not establish a public procedure to import a user's Blooio account. [Keiki channels](https://onkeiki.com/docs/channels#imessage-lines), [iMessage setup guide](https://onkeiki.com/blog/how-to-add-imessage-to-your-ai-agent), [Group chats](https://onkeiki.com/docs/cloud-agents#group-chats)
- **Provisioning.** The dashboard connects imported lines. Keiki's management MCP documentation excludes provider-account key imports. A partner deployment can request a count of iMessage lines and buys only the missing number of lines on an upsert. Check each channel result, including `needs_payment`. `kit.sync()` does not forward channel identities, and replies use the line bound to the conversation. A dashboard move between Keiki agents is distinct from a provider account import or carrier port. [Keiki MCP](https://onkeiki.com/docs/mcp#tools), [Partner deployments](https://onkeiki.com/docs/partner-deployments#channels), [AgentKit](https://onkeiki.com/docs/sdk#agent-lifecycle), [Keiki changelog](https://onkeiki.com/blog/changelog-2026-10-29#connect-more-lines-and-request-an-apple-business-channel)
- **Inbound and outbound.** Choose and document event ingress, send path, media transport, and work lifecycle independently. External turns can batch a burst, suppress some inbound activity or route it to a separate reaction or consent event. A webhook receiving every provider event needs a demonstrated mapping for each required event and lifecycle. [External harness](https://onkeiki.com/docs/external-harness), [Event webhooks](https://onkeiki.com/docs/webhooks)
- **Conversation and delivery.** Verify direct chat, group, fallback and proactive cases independently. Test actual recipient and sender identity, scoped message IDs, reply binding and line eligibility. Match native features and timing to the chosen type of line and the surface emitting the action. The model gateway only establishes an API conversation contract. Apple Messages for Business has its own customer-initiated channel, onboarding, and supported actions. [Keiki channels](https://onkeiki.com/docs/channels#what-each-channel-supports), [Notices and line selection](https://onkeiki.com/docs/agent-api#notices-from-your-server), [Apple Messages for Business](https://onkeiki.com/docs/apple-messages-for-business)

## Record the architecture and cutover

For each active boundary, record the current caller, selected Keiki API or tool, owner, authentication, identifier mapping, and behavior under failure or retry. Compare affected files, runtime, hosting, dependencies, credentials, lifecycle, operational changes and verification cost. Explain why any change in transport is required and how its behavior is verified.

When combining surfaces, record which owns each action and event, credential and ID bindings, acknowledgement, duplicate prevention, reconnect or lease behavior, unknown-send handling, and shutdown where applicable. If the existing provider remains underneath an imported line or retains an active app responsibility, identify the resulting dependency explicitly. A split migration needs one authoritative sender and receiver for each applicable path.

Record how contacts, line assignments, source IDs, pending sends, in-flight turns, deduplication keys, transcripts, attachments, and consent state carry forward where applicable. Keiki binds replies to the line already associated with the conversation. A new line or changed join flow needs its own contact transition. Confirm ownership and rollback before changing webhook routing or releasing a line. [Notices and line selection](https://onkeiki.com/docs/agent-api#notices-from-your-server), [Partner channel lifecycle](https://onkeiki.com/docs/partner-deployments#read-and-delete)

Use [the Keiki evidence guide](./keiki-evidence.md) to establish exact mappings. Compare alternative Keiki surfaces when an active behavior remains unresolved. Keep the unresolved behavior in the migration plan and identify the evidence or explicit scope decision needed before that behavior can be switched.
