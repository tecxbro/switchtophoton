# Choosing the Keiki target

Identify the source integration, its exact API generation, and the active behavior before choosing a Keiki surface. Keiki runs messaging channels for agents. A provider integration that sends to arbitrary recipients, manages Apple identities, or processes raw message events may need capabilities beyond Keiki's public agent interfaces.

## Choose the turn runtime

| Current boundary | Keiki surface to evaluate | Migration implications |
| --- | --- | --- |
| The application owns a model loop or deterministic reply handler behind an HTTPS receiver | [External harness in push mode](https://onkeiki.com/docs/external-harness#configure-an-agent) | Keep the handler and hosting model where possible. Adapt the receiver to signed, asynchronous turns and use scoped delivery and completion calls. Prove that source behavior still holds when Keiki batches, steers, or suppresses inbound messages. |
| The application runs locally, behind a firewall, or intermittently | [External harness in relay or inbox mode](https://onkeiki.com/docs/external-harness#relay-mode) | Relay forwards signed turns from a queue to the application. Inbox long-polls and uses leased claims. Compare queue, cancellation, arrival, and reaction semantics against the current lifecycle. |
| The migration is to a Keiki-managed agent with prompts and tools | [Cloud-served agents](https://onkeiki.com/docs/cloud-agents) and [AgentKit](https://onkeiki.com/docs/sdk#agent-lifecycle) | The dashboard or `kit.sync()` configures the agent. Keiki runs the turn loop, channel routing, and delivery. Map existing prompts, tools, state, and response behavior before moving the loop. |
| The application will run a Keiki SDK-defined agent on its own host | [AgentKit `kit.serve()`](https://onkeiki.com/docs/sdk#self-hosting-server) | The SDK syncs the configuration and serves its own Keiki-authenticated routes. Check runtime and hosting requirements. The server answers its turn request synchronously, while the external harness delivers and settles turns asynchronously. |
| Your backend provisions one agent per user or organization | [Partner deployments](https://onkeiki.com/docs/partner-deployments) | Keep the application tenant key in `external_ref`. Provisioning and channel connection have their own result statuses and billing effects. Choose the turn runtime separately. |
| A caller wants to invoke an agent through a model API | [Agents as models](https://onkeiki.com/docs/agent-api) | The OpenAI- or Anthropic-compatible gateway returns an API-channel completion. Use it for API callers. Channel delivery and inbound iMessage still require their own route. |

Use an existing framework adapter when it matches the application and its runtime. Check the [AI SDK](https://onkeiki.com/docs/ai-sdk), [Flue](https://onkeiki.com/docs/flue), or [Eve](https://onkeiki.com/docs/eve) contracts. [Keiki MCP](https://onkeiki.com/docs/mcp) can configure and inspect the platform. A production harness can use the turn MCP interface when it needs the turn's tools. Ordinary HTTP harnesses can use the documented turn endpoints.

## Choose channel and delivery separately

- **Line and identity.** Confirm the intended agent, actual line type and provider, recipient and line identifiers, routing for multi-line agents, and availability for the intended account. Keiki documents dedicated bought or imported lines and shared numbers. The first text to a shared number must include the agent's join code. Provider-specific eligibility and retention of the same number need evidence for the particular line. The official setup example documents importing Linq lines and connecting a Photon account. [Keiki channels](https://onkeiki.com/docs/channels#imessage-lines), [iMessage setup guide](https://onkeiki.com/blog/how-to-add-imessage-to-your-ai-agent)
- **Conversation coverage.** Verify direct, group, and fallback paths separately. Keiki group intake requires a dedicated `photon` or `blooio` line and the Group chats feature. The agent applies addressing and quiet-context rules. `linq` lines and shared numbers ignore group traffic. Apple Messages for Business is a separate customer-initiated channel with its own onboarding and supported actions. [Group chats](https://onkeiki.com/docs/cloud-agents#group-chats), [Keiki channels](https://onkeiki.com/docs/channels#what-each-channel-supports), [Apple Messages for Business](https://onkeiki.com/docs/apple-messages-for-business)
- **Inbound and outbound.** For external apps, map source events to turn messages, arrivals, cancellations, or separately documented events. Turns carry bounded history, scoped identifiers, and attachments where available. Use the supplied turn URL for replies and native actions. With a hosted agent, map the same requirements to available agent tools and verify their effects on the selected line. [External harness](https://onkeiki.com/docs/external-harness), [Cloud-served agents](https://onkeiki.com/docs/cloud-agents)
- **Proactive sends.** An `agents:write` key for the selected agent can call `POST /api/v1/developer/agents/:agentId/notice` with `phone` to start a turn in that agent's existing conversation. An external handler can deliver explicit text with `POST {turnUrl}/messages` using that active turn's bearer and its bound conversation and line. Check recipient eligibility, opt-outs, and any reply requirement. A new identity returns 404 and omitting `phone` broadcasts to recent conversations. SDK alerts target subscribers. For workflows that initiate conversations, require a public send operation and evidence for recipient eligibility, ownership, and authorization before mapping that behavior. [Notices from your server](https://onkeiki.com/docs/agent-api#notices-from-your-server), [Proactive turns](https://onkeiki.com/docs/external-harness#proactive-turns), [AgentKit alerts](https://onkeiki.com/docs/sdk#alerts)
- **Media and actions.** Confirm each needed action and media type on the chosen runtime, line and transport. Instant, Standard, and on-request lines have different capabilities. SMS/RCS fallback has a smaller set of actions. Message replies, tapbacks, edit, unsend, effects, and files also depend on the conversation and the surface used to send them. [Keiki channels](https://onkeiki.com/docs/channels#what-each-channel-supports), [Turn-scoped API](https://onkeiki.com/docs/external-harness#turn-scoped-api)
- **Events and consent.** External turn dispatch is an agent execution contract. Use the event webhook subscription for consent changes. Verify required raw provider behavior independently, including history backfill, arbitrary chat lookup, read and delivery receipts, group management, and event ordering. Keiki dashboard visibility alone supplies no application event contract. [External harness](https://onkeiki.com/docs/external-harness), [Event webhooks](https://onkeiki.com/docs/webhooks)

## Record the architecture and cutover

For each active boundary, record the current caller, selected Keiki API or tool, owner, authentication, identifier mapping, and behavior under failure or retry. Name affected files and hosting changes. When a source provider remains underneath an imported Keiki line, account for who controls that line and which system may send, receive, or retry at each cutover stage.

Record how contacts, line assignments, source IDs, pending sends, in-flight turns, deduplication keys, transcripts, attachments, and consent state carry forward where applicable. Keiki binds replies to the line already associated with the conversation. A new line or changed join flow needs its own contact transition. Confirm ownership and rollback before changing webhook routing or releasing a line. [Notices and line selection](https://onkeiki.com/docs/agent-api#notices-from-your-server), [Partner channel lifecycle](https://onkeiki.com/docs/partner-deployments#read-and-delete)

Use [the Keiki evidence guide](./keiki-evidence.md) to establish exact mappings. Compare alternative Keiki surfaces when an active behavior remains unresolved. Keep the unresolved behavior in the migration plan and identify the evidence or explicit scope decision needed before that behavior can be switched.
