# Keiki iMessage capabilities and gaps

Public documentation and pinned packages checked on 2026-11-14. Use this reference to build the active capability map for the source app. Recheck the specific Keiki runtime, account, line and provider chosen for the migration. [Evidence and status definitions](./keiki-evidence.md)

## Current migration scope

Keiki replaces the source integration. Use Keiki's built-in action for each supported operation. On an eligible iMessage line the Keiki agent can attach a native 👍 to the incoming message when asked. A hosted agent uses its built-in tool. An external harness can expose the tools for the active turn or invoke the documented action using the turn's scoped message ID. Remove the old provider-specific tool so the agent has a single delivery path. [Hosted iMessage actions](https://onkeiki.com/docs/cloud-agents#imessage), [External harness actions](https://onkeiki.com/docs/external-harness#native-channel-actions)

- **Replace:** Map supported text and native actions to the chosen Keiki line and runtime. An external responder uses signed `keiki.turn` dispatch and the scoped actions before calling `/complete`.
- **Remove with approval:** List each active behavior without a proven equivalent and what users will lose. For a placed sticker, remove the old tool, placement parameters and any prompt that offers it. A plain emoji, image file or disabled trigger is a user-visible change.
- **Block:** A required behavior with no mapping and no approved removal blocks the switch. Every executable plan ends with the old provider integration removed.

| Send screen and bubble effects | `POST {turnUrl}/messages` accepts an `effect` string. The public contract makes `effect` and `replyToMessageId` mutually exclusive. | Prove the exact accepted effect names or identifiers for every active source value. [Turn-scoped API](https://onkeiki.com/docs/external-harness#turn-scoped-api), [iMessage channel behavior](https://onkeiki.com/docs/cloud-agents#imessage) |
| Native text decorations and combined payloads | Source APIs can apply native styles and animations to part ranges, target a particular part, or combine media and an effect in one message. Keiki's documented text and file actions expose separate payloads, with no public mapping established for range decorations, part index or file effect. | Verify each active combination as a single recipient-visible result. ## Public documentation that would resolve gaps

Keiki can make these migrations easier to verify by publishing:

- A line and provider matrix with exact accepted Tapback, effect and attachment inputs, native sticker operations and supported group actions, including errors and runtime eligibility.
- The contract for initiating a conversation or sending outside an existing turn, with sender and recipient selectors, scoped credentials, allowed line types, consent, and idempotency and retry behavior.
- An event catalog for delivery and read states, typing, edits and group changes, with each runtime's supported events, stable identifiers, delivery guarantees and sample payloads. Include a versioned inbound envelope that identifies the actual iMessage, SMS or RCS transport, receiving line, and available phone or Apple Account identifiers.
- Provider-specific import and rollback procedures and supported migration formats for prior transcripts, attachments, identifiers, sender aliases, consent and existing subscriber or line assignments.
- A package compatibility matrix and release verification for the external harness adapters, with exact supported versions, import smoke tests and the hosted features each client exports.
