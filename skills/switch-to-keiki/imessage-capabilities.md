# Keiki iMessage capabilities and gaps

Public documentation and pinned packages checked on 2026-11-14. Use this reference to build the active capability map for the source app. Recheck the specific Keiki runtime, account, line and provider chosen for the migration. [Evidence and status definitions](./keiki-evidence.md)

## Current migration scope

Native iMessage reactions and stickers are unavailable in the current Keiki rollout for this skill, per product confirmation on 2026-11-14. Public Keiki docs describe `react` and `keiki.reaction`. Record that discrepancy as evidence. Exclude those operations from Keiki implementation plans until product support confirms a specific shipping surface, line and runtime and the behavior is then verified.

- **Full switch:** Eligible when the app uses only behaviors proven on the chosen target. An inbound text responder can move its messaging boundary to signed `keiki.turn` dispatch, turn-scoped `/messages`, and `/complete` while keeping its app logic.
- **Partial switch:** Keep a reaction- or sticker-dependent workflow on the source provider. Move another workflow only when both can run independently with a clear line or conversation owner. Keep the provider message IDs and reaction handlers with the retained workflow.
- **Blocked:** If an active workflow relies on a reaction or sticker and has to move as a unit, keep that workflow on the source provider. A plain text emoji, PNG file, or disabled reaction trigger changes the product and requires explicit approval.

## Public documentation that would resolve gaps

Keiki can make these migrations easier to verify by publishing:

- A line and provider matrix with exact accepted Tapback, effect and attachment inputs, native sticker operations and supported group actions, including errors and runtime eligibility.
- The contract for initiating a conversation or sending outside an existing turn, with sender and recipient selectors, scoped credentials, allowed line types, consent, and idempotency and retry behavior.
- An event catalog for delivery and read states, typing, edits and group changes, with each runtime's supported events, stable identifiers, delivery guarantees and sample payloads. Include a versioned inbound envelope that identifies the actual iMessage, SMS or RCS transport, receiving line, and available phone or Apple Account identifiers.
- Provider-specific import and rollback procedures and supported migration formats for prior transcripts, attachments, identifiers, sender aliases, consent and existing subscriber or line assignments.
- A package compatibility matrix and release verification for the external harness adapters, with exact supported versions, import smoke tests and the hosted features each client exports.
