# Photon source reference

## Official documentation

Reviewed 2026-11-14. Start with the [Photon LLM index and version indicators](https://photon.codes/docs/llms.txt). Use the matching [Stable Spectrum iMessage guide](https://photon.codes/docs/spectrum-ts/providers/imessage), [Spectrum SDK webhooks](https://photon.codes/docs/spectrum-ts/webhooks.md), [Advanced iMessage Kit](https://photon.codes/docs/advanced-kits/imessage/messages.md), or [Photon 2.0 Beta iMessage guide](https://photon.codes/docs/beta/messaging/imessage.md).

## Detection

- Stable Spectrum signals include `spectrum-ts`, `@spectrum-ts/*`, `spectrum.photon.codes`, and project ID/secret configuration. Cloud `imessage` and macOS `local_imessage` can coexist in one app. Distinguish `@spectrum-ts/imessage`, `@spectrum-ts/imessage-local`, and the earlier `imessage.config({ local: true })` form using the installed version and active entry points. [Stable Spectrum iMessage guide](https://photon.codes/docs/spectrum-ts/providers/imessage)
- Also inspect `@photon-ai/advanced-imessage`, `@photon-ai/advanced-imessage-kit`, `@photon-ai/imessage-kit`, and the legacy iMessage Chat SDK adapter. Confirm direct client calls, an Apple Messages database on a Mac, a hosted line, or a proxy from source configuration and tests. [Legacy iMessage Chat SDK integration](https://photon.codes/docs/integrations/chat-sdk.md), [Advanced iMessage Kit](https://photon.codes/docs/advanced-kits/imessage/messages.md)
- Photon 2.0 Beta signals include `api.photon.codes/v1`, `@photon-ai/api`, `photonhq-api`, `@photon-ai/chat-adapter`, and bearer credentials. Record the actual SDK lockfile version, host, REST paths, credential types, and subscribed transports. Record both generations when active call sites or deployments prove mixed use. [Photon LLM index and version indicators](https://photon.codes/docs/llms.txt)

## Behavior to inventory

- Identify how messages enter each application path. Stable Spectrum may use SDK streams or request-scoped webhooks, with native JSON or Fusor protobuf. Webhook handling via `app.webhook()` does not feed `app.messages`. Photon 2.0 Beta has signed HTTPS webhooks and a Socket.IO event stream with a resume cursor. Record relevant signature checks, deduplication keys, event ordering, reconnect, and replay behavior. [Spectrum SDK webhooks](https://photon.codes/docs/spectrum-ts/webhooks.md), [Beta webhook](https://photon.codes/docs/beta/message-delivery/webhook.md), [Beta WebSocket](https://photon.codes/docs/beta/message-delivery/websocket.md)
- Trace active outbound sends and replies, cloud token renewal versus explicit client tokens, line selection and platform narrowing, group routing, space identifiers, device state, and handling of partial failures or retries. Verify plan and runtime restrictions using the matching surface.
- Inventory active use of attachments and lazy reads, native effects or app cards, edits and unsend, tapbacks, typing, read receipts, groups, and any SMS, WhatsApp, Telegram, or voice features registered alongside iMessage. Check whether conversation history, thread and message IDs, or attachment references are tied to the original project, line, Mac, or application cache.

## Map a direct inbound reply

1. Pin the active library and imported provider shape. For Stable Spectrum identify `app.messages` versus `app.webhook()`, native JSON versus Fusor protobuf, and `imessage` versus `local_imessage`. For Beta identify raw HTTPS/SDK, signed webhook or resumable Socket.IO, event schema and event cursor. For a legacy proxy or direct kit identify the exact host, per-line routing and connection lifecycle from the installed package and fixtures. [Stable Spectrum messages](https://photon.codes/docs/spectrum-ts/messages.md), [Stable SDK webhooks](https://photon.codes/docs/spectrum-ts/webhooks.md), [Beta WebSocket](https://photon.codes/docs/beta/message-delivery/websocket.md)
2. Choose the Keiki agent and line. Keiki documents connecting a Photon account. Verify the exact project's line eligibility and intended number. A Spectrum local Apple account, Mac database, or explicit client token requires a separate transition decision. Inventory registered non-iMessage providers and preserve their paths. [Keiki setup](https://onkeiki.com/blog/how-to-add-imessage-to-your-ai-agent), [Photon line routing](https://photon.codes/docs/spectrum-ts/providers/imessage/connection-and-routing.md)
3. Convert the application-owned model loop or deterministic handler to accept `keiki.turn` or an approved inbox/relay boundary. Record the difference between a source stream item or event and an agent turn, including batching, quiet handling, cursor/resume requirements and how source markers prevent own-message loops. [Keiki external harness](https://onkeiki.com/docs/external-harness)
4. Replace the approved `space.send` or source send/reply operation with a bound-turn call. Use `POST {turnUrl}/messages` for text and optional native thread, and `/attachments` and `/actions` for eligible files. Use stable per-send keys and await settlement before acknowledging completion. [Keiki turn API](https://onkeiki.com/docs/external-harness#turn-scoped-api)

| Source field or behavior | Keiki mapping and evidence to retain |
| --- | --- |
| Spectrum `[space, message]`, `space.id`, `message.id`, `message.sender?.id` and `message.platform` | Use `agentId`, `conversationId` and scoped `messages[].messageId` for new work. Resolve the app's sender and tenant only from documented captured target context. Preserve source platform split and opaque IDs as old-system references. |
| Stable `message.content.type`, `message.content.text` and native attachment `read()` | Map text to `messages[].text`; use `content` for model-ready annotations. Read `messages[].attachments` through its signed URL or the authenticated turn route while the turn is open. Check grouped parts, content types, file readiness and expiry where active. |
| Beta public event `id`, webhook `webhook-id` or Socket.IO receive cursor | Deduplicate authenticated Keiki dispatch by `turnId` and its sends by stable idempotency keys. Arrival sequences belong to an open turn. Verify the old project-event audit/recovery boundary separately. |
| Native reply, reaction, or group destination | Cite the target turn's `messageId` for a native reply or reaction. The turn is pinned to its conversation and line. Group recipient state and the old project chat GUID remain separate from Keiki IDs. |

## Determine how much can move

- **Full for the active scope, conditional until verified.** Stable cloud and Beta 1:1 inbound/reply flows can move when selected line, contact permissions, typed content and lifecycles match. Addressed replies in an existing group can move on eligible dedicated `photon` lines with Group chats enabled, subject to Keiki's group-addressing and quiet-context rules. Test edits/unsend individually within channel and Apple time limits. [Keiki channels](https://onkeiki.com/docs/channels), [Keiki group chats](https://onkeiki.com/docs/cloud-agents#group-chats)
- **Partial for raw project or Mac dependencies.** Preserve source event consumers needing ordered/cursor-resumable Beta feeds, Stable membership or read events, local database history, or separate Photon channels if no equivalent was proven. Channel attachments, group administration, app cards, native polls, background changes and in-flight delivery are distinct mappings. [Photon group membership](https://photon.codes/docs/spectrum-ts/providers/imessage/messaging-features/group-membership.md), [Photon read receipts](https://photon.codes/docs/spectrum-ts/providers/imessage/messaging-features/inbound-read-receipts.md), [Keiki event webhooks](https://onkeiki.com/docs/webhooks)
- **Blocked for app cards on imported lines** where the active source behavior needs card delivery on that same line. Keiki URL cards require a dedicated eligible line bought in Keiki, direct iMessage and Dynamic UI. Its verified custom extension setup does not establish continuity of existing card sessions or synchronous updates. Required arbitrary new-contact sends, exact chat administration or same Apple account/local DB continuity remain unresolved on the documented agent/turn surfaces. [Keiki app cards](https://onkeiki.com/docs/imessage-apps), [Keiki notices](https://onkeiki.com/docs/agent-api#notices-from-your-server)

## Cutover and acceptance

Record source project or Mac, local/cloud platform, sender line, chat GUIDs, reply targets, attachment IDs and pending sends. Partition source and Keiki reply ownership before changing ingress or subscription routing. Keep the last committed source event/cursor or Mac checkpoint for a rollback. Verify that any retained local/cloud streams still process only their intended lines and that the application cannot acknowledge or send twice through the two runtimes.

Use redacted Stable stream/webhook and Beta socket/webhook fixtures for whichever paths are active. Test own-message echo, two burst entries, native reply, matched and mismatched line, invalid signature, duplicate message/event/turn, attachment timeout, aborted turn, unknown delivery, and reconnect/replay for any retained cursor consumer. Verify addressed group reply, quiet context, and unsupported-line behavior where groups are active. Photon publishes the [basic Spectrum example at the reviewed commit](https://github.com/photon-hq/spectrum-ts/tree/461ab57c1b49b6d3f9a0693cc796be3156649f77/examples/basic) and [core transport and content tests](https://github.com/photon-hq/spectrum-ts/tree/461ab57c1b49b6d3f9a0693cc796be3156649f77/packages/core/test). Run verification with mocked providers.
